# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Primary users are recruiters, hiring managers, engineers, and collaborators evaluating Kyle Young for mechanical engineering, robotics, aerospace/manufacturing, product development, or research roles.

## Product Purpose

This is Kyle Young's personal engineering portfolio. It helps visitors quickly understand his capabilities, evidence of hands-on work, project range, professional experience, leadership, and ways to contact him.

Success means a visitor can quickly identify relevant experience, inspect credible project evidence, understand Kyle's engineering strengths, and take the next step through email, resume download, LinkedIn, or GitHub.

## Positioning

The portfolio emphasizes the full engineering loop: defining problems, designing systems, validating ideas, manufacturing hardware, testing outcomes, and learning from results.

Kyle's work spans Formula SAE, robotics, aerospace manufacturing support, biomedical flow research, additive-manufacturing thermal research, and 3D printed product development. The durable position is hands-on, product-minded mechanical engineering across analysis, CAD/design, fabrication, testing, leadership, and practical execution.

## Operating Context

The product is a static personal website intended for free static hosting such as GitHub Pages or Cloudflare Pages.

Visitors use it as a fast evaluation surface: scanning the homepage, opening project pages, checking professional and leadership experience, downloading the resume, and contacting Kyle through email, LinkedIn, or GitHub.

## Capabilities and Constraints

The site is built with static HTML, CSS, and JavaScript. The main entry is `index.html`; shared styling lives in `style.css`; shared behavior lives in `script.js`; project detail pages live under `projects/`.

The site includes responsive navigation, reveal animations, project cards, project detail pages, image fallbacks, resume download, email contact, LinkedIn, and GitHub links.

Future work must preserve the static-site constraint unless Kyle explicitly changes the technical direction. It should not depend on a backend or fabricate dynamic product capabilities.

## Brand Commitments

The product name and identity center on Kyle Young. The existing portfolio presents him as a UCLA Mechanical Engineering student, founder, and builder.

Durable content commitments include Kyle Young's name, UCLA Mechanical Engineering, the listed project and experience content, resume/contact pathways, and the existing professional focus areas.

## Evidence on Hand

Repository evidence includes:

- `index.html`: homepage content, project summaries, professional experience, leadership, background, contact, resume, LinkedIn, and GitHub links.
- `projects/`: project detail pages for engineering, robotics, Formula SAE, product design, and research work.
- `README.md`: static hosting notes, expected asset paths, and recent content-update notes.
- `images/`: referenced project and headshot imagery when present.
- `YoungKyle_Resume.pdf`: expected resume file path referenced by the site.

Future work must not invent testimonials, clients, metrics, awards, press, deployment claims, or proof assets. Use only real evidence in the repository or facts Kyle explicitly confirms.

## Product Principles

1. Lead with credible engineering evidence over generic self-promotion.
2. Make the full path from problem to design, manufacturing, testing, and learning easy to see.
3. Preserve factual accuracy, especially around roles, metrics, awards, and technical claims.
4. Keep project exploration fast for evaluators with limited time.
5. Make contact and resume access obvious without distracting from the work.

## Accessibility & Inclusion

No product-specific accessibility standard has been confirmed beyond normal web portfolio expectations. Future work should preserve responsive access and avoid patterns that prevent keyboard, screen reader, or reduced-motion use.
